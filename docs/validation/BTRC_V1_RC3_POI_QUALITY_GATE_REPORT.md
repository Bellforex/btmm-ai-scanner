# BTRC-V1 RC3 — POI Quality Gate Report (Phase 8)

**Status:** documentation/analysis only; no code, test, Pine or register change.
**Scope:** the 18 lifecycle-eligible core types (`poi/enums.py:114-133`; REG §35V, REG:4612).
**Citations:** code paths relative to `src/btmm_ai_scanner/`; "cfg" = `poi/configuration.py`; "REG:n" = `docs/architecture/PHASE_1B_AUTHOR_DECISION_REGISTER.md` line; "MS:n" = `knowledge/MEASUREMENT_STANDARDS.md` line; "KB <file>:n" = `knowledge/poi_rules/**`.
**Reading rule:** "Mandatory" = the code rejects the candidate (no `PoiObservation`) when the condition fails. "Optional / descriptive" = register or KB wording that is explicitly non-gating; nothing optional here is upgraded to mandatory. Disagreements are listed in section 3, not resolved.

Shared facts:
- All detectors use `total_range = high - low` (`measurements/candle_metrics.py:10-11`), `body_efficiency = |close-open| / range`, 0 when range is 0 (`:18-22`), wick and close-position helpers (`:25-44`).
- Every detector runs independently; the only post-filter is `enabled_poi_types` (`poi/analyzer.py:389-409`). The incremental path calls the same detector functions on bounded slices (`poi/detector_frontier.py:319-343`); bases have their own frontier implementation (`poi/detector_frontier.py:181-300`).
- No POI detector has a structure, trend or swing-context input (REG:4578,4584). Tier `STANDARD`/`STRONG` is descriptive strength, not a gate.
- Lifecycle, shared by all 18 types: Contact Tolerance `MAX(2 tick, MIN(0.05 ATR, 0.10 H))`, Overshoot Tolerance `MAX(2 tick, MIN(0.10 ATR, 0.25 H))`, reclaim and displacement windows of 3 bars (REG:4608-4623; cfg:62-68).

## 4. Genuine ambiguities (not resolved here)

- **S/R availability vs touch-swing availability:** zone availability is the touch-reaction MFE candle close (`support_resistance.py:279,299`); the reaction search starts at `touch pivot end + 1` (`:263-268`), while the touch swing's own availability is `meaningful_confirmation_time_utc` (`domain/analyzer.py:318`). The code does not take the max of the two. Whether real data ever produces a zone available before its touch swing was not measured.
- **Tier naming:** register/KB name tiers `COMPACT_BASE`/`STRONG_BASE`, `STANDARD_PATTERN`/`STRONG_PATTERN`, `DRAFT/CONFIRMED/STRONG_SUPPORT` (REG:4517; MS:1599-1608,1425-1429); code emits `STANDARD`/`STRONG` or no tier (FVG, S/R). Mapping is implicit.
- **FVG D1 scope:** REG:4499 calls the small-candle comparison mandatory, while KB buy_fair_value_gap.md:29 calls the speed measurement "a separate, optional quality signal". Only the author can say whether the small-candle comparison (not the speed tiers) was meant to gate.
